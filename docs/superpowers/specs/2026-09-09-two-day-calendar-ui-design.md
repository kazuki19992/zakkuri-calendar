# 2日ビュー中心のカレンダーUI設計

## 1. 目的

Issue #15では、起動直後に直近の予定へ到達しやすい2日ビューを提供し、月ビューとの切り替え、独自カレンダー描画、ライト・ダーク両方の落ち着いたテーマを実装する。

このPRでは予定を日ごとのリストとして表示する。時間軸上の配置と曖昧さのグラデーションは、このPRの直後にIssue #17で実装する。

## 2. 決定事項

- MVPの初期表示は、今日を基準日とした今日・明日の2日ビューとする。
- 2日ビューは横2列で表示する。
- 前後操作と横スワイプでは、基準日を1日単位で移動する。
- 移動単位は実機で触った後に変わる可能性があるため、hookの期間移動関数へ閉じ込める。
- 2日ビューと月ビューは同じ画面上のセグメント操作で切り替える。
- MVPでは選択中のビューを永続化しない。v1の復元はIssue #16で実装する。
- `react-native-calendars`を削除し、月グリッドもReact Nativeの標準コンポーネントで描画する。
- 日本の祝日判定は既存の`@gahojin-inc/holiday-japanese`と`HolidayProvider`境界を維持する。
- 具体的な時間軸とグラデーションはIssue #17の対象とする。

## 3. 画面構成

画面上部から次の順に配置する。

1. `CalendarViewSwitcher`
   - 「2日」「月」の2つを表示する。
   - 選択状態は背景色だけでなく、太字、枠、`accessibilityState.selected`で伝える。
2. `CalendarPeriodToolbar`
   - 前期間、現在の期間ラベル、今日、次期間を表示する。
   - 2日ビューでは1日、月ビューでは1か月移動する。
3. 表示中のカレンダー
   - 2日ビューでは`TwoDayView`を表示する。
   - 月ビューでは独自実装の`MonthGrid`を表示する。
4. 月ビュー選択日の予定一覧
   - 現在の選択日一覧と追加導線を維持する。

### 3.1 2日ビュー

`TwoDayView`は基準日とその翌日を同じ幅の横2列で表示する。初期状態だけが今日・明日であり、移動後も同じ構造を保つ。各`TwoDayColumn`は次を持つ。

- 月日、曜日
- 今日であることを示す文字・枠
- 祝日名
- 予定タイトル
- 「朝」「午後」などの時間表現ラベル
- 空状態
- その日を初期値にした予定追加操作

小さい画面と文字拡大では列の幅を維持したまま縦方向へスクロールできる構造とする。予定タイトルは省略可能だが、アクセシビリティラベルには完全なタイトルと時間表現を保持する。

### 3.2 月ビュー

月ビューは7列×6行をReact Nativeの`View`と`Pressable`で描画する。既存の月日付モデル、祝日モデル、日付セルのアクセシビリティ情報は再利用する。

- 月曜日始まりはMVPの固定値とする。
- 前月・次月の日も表示する。
- 今日、選択日、予定あり、土曜、日曜・祝日を色以外でも識別できる。
- 月グリッド自体は外部カレンダーUIライブラリへ依存しない。

## 4. 状態とデータフロー

`useCalendarView`を画面の状態調整境界とする。

```text
IndexRoute
  -> RepositoryとHolidayProviderを注入
  -> useCalendarView
       -> 表示モード
       -> 基準日・表示月・選択日
       -> 表示範囲の予定・祝日取得
       -> 2日／月の表示用モデル生成
       -> 前後移動、今日、日付選択、再試行
  -> CalendarScreen
       -> CalendarViewSwitcher
       -> CalendarPeriodToolbar
       -> TwoDayView または MonthGrid
```

UIコンポーネントはSQLite、Repository、祝日ライブラリへ直接アクセスしない。日付範囲計算は`src/domain/calendar`の純粋関数へ置き、`date-fns`を利用する。

`CalendarViewMode`は`'twoDay' | 'month'`とする。初期値は常に`twoDay`で、`TODO(v1, #16)`を残す。ビュー追加を見越した汎用レジストリは作らない。

2日ビューの移動量は`moveTwoDayWindow(anchorDate, offset: -1 | 1)`で表し、現在は1日移動とする。UIやスワイプhookへ日数を埋め込まない。

## 5. 横スワイプとアニメーション

`useHorizontalSwipeTransition`がPanResponderと`Animated.Value`を管理する。

- 水平移動が垂直移動を上回り、距離・速度の閾値を超えた場合だけ期間移動を確定する。
- ドラッグ中は表示内容を指へ追従させる。
- 確定時は現在内容を操作方向へスライドアウトする。スライドさせる距離は、計測した画面幅に対する比率(`stepRatio`)で指定し、1回の移動が更新する範囲と一致させる。月ビューは1か月まるごと更新するため画面全体(比率1)、2日ビューは基準日を1日分だけ動かすため画面の半分(比率0.5)とする。
- 対象範囲の取得完了後、新しい内容を反対側からスライドインする。
- 取得失敗時は元の期間へ戻し、再試行可能なエラーを表示する。
- アニメーション中は追加の期間移動を受け付けない。
- 前後ボタンも同じ遷移関数を利用する。
- OSのReduce Motionが有効な場合は、位置アニメーションを行わず内容を切り替える。

アニメーションはReact Native標準の`Animated`を利用し、新しい依存は追加しない。時間、距離、閾値はhook内の定数へまとめ、表示コンポーネントへ散在させない。

## 6. テーマ

配色はNotionを参考に、白・チャコール・暖色系グレーを基調とする。ブランド固有の色を複製するのではなく、高彩度の原色を避けたカレンダー向けのsemantic tokenとして定義する。

| token | light | dark | 用途 |
| --- | --- | --- | --- |
| `text` | `#37352F` | `#EDECE9` | 本文・見出し |
| `background` | `#FFFFFF` | `#191919` | 画面背景 |
| `backgroundElement` | `#F7F6F3` | `#252525` | 補助面 |
| `backgroundSelected` | `#E9E7E2` | `#34312D` | 選択状態 |
| `textSecondary` | `#787774` | `#9B9A97` | 補助文字 |
| `calendarAccent` | `#8B6F5A` | `#C6A58A` | 主要操作・今日 |
| `calendarSaturday` | `#4D708C` | `#8EA9BF` | 土曜 |
| `calendarHoliday` | `#A55B4B` | `#D08A78` | 日曜・祝日・エラー |
| `calendarBorder` | `#D8D5CF` | `#3F3E3B` | 境界線 |

色だけで状態を伝えず、選択枠、下線、ラベル、チェック、読み上げ情報を併用する。予定作成モーダルを含め、既存の`useTheme`利用箇所も同じtokenへ追従させる。

## 7. エラー・空状態

- 初回取得失敗は画面全体のエラーと再試行を表示する。
- 期間移動の取得失敗は現在表示を失わず、移動を取り消して再試行可能にする。
- 予定がない2日列には、その日単位の空状態と追加操作を表示する。
- 祝日情報の対応範囲外は「祝日情報未対応」と表示し、祝日なしと区別する。
- 非同期取得は古い応答で現在の表示を上書きしない。

## 8. テスト

新しいコメント、`describe`、`test`、`it`の説明は日本語にする。

- domain: 2日範囲、1日単位移動、月・年境界
- hook: 2日ビュー初期値、月切替、表示範囲取得、今日復帰、古い応答の無視、移動失敗
- gesture hook: 距離・速度・縦方向判定、移動方向、アニメーション中の再入力、Reduce Motion、`stepRatio`指定時・省略時のスライド距離
- components: 横2列、空状態、祝日、予定ラベル、追加日付、月7列×6行
- theme: ライト・ダークのsemantic tokenと選択状態
- integration: 2日／月切替後の予定取得と保存後再読み込み
- repository全体: typecheck、lint、全テスト、iOS・Android export

自動テストとexportは実機レイアウトやアニメーションの証明にはしない。iOS・Androidでスワイプ追従、小さい画面、文字拡大、ライト・ダークを確認し、未確認項目をPRへ明記する。
