# 予定編集・正確な時間入力・追加導線 設計

## 1. 目的

MVPで作成済みの日内ざっくり予定を、Googleカレンダーに近い導線で作成・編集・削除できるようにする。正確な予定は開始時刻と終了時刻を指定して作成し、2日ビューでは時間位置から素早く作成できるようにする。

関連Issue: [#1 MVP](https://github.com/kazuki19992/zakkuri-calendar/issues/1)

## 2. 対象範囲

### 2.1 実装すること

- カレンダー画面右下の常設「予定を追加」ボタン
- 選択日、現在時刻から1時間の正確な予定を初期値とする新規フォーム
- 2日ビューのタイムラインをダブルタップした日時から、最も近い`HH:00`を開始時刻とする新規フォーム
- 既存予定のタップによる編集フォーム表示
- タイトル、日付、種別（正確・終日・ざっくり）の変更
- 正確な予定の開始時刻・終了時刻のネイティブピッカー入力
- ざっくり予定の日内時間表現の選択
- 予定の削除とネイティブ確認ダイアログ
- 保存・削除後のカレンダー表示の即時再読込

### 2.2 対象外

- 週・月粒度のざっくり予定の作成UI
- 期間をまたぐ繰り返し予定
- 独自の日時ピッカー実装
- 通知、外部カレンダー連携、共有、クラウド同期

ネイティブピッカーは、将来独自の日時選択UIへ置き換える前提で表示コンポーネント内に閉じ込める。

## 3. 操作フロー

### 3.1 新規予定

1. カレンダー画面右下の「予定を追加」を押す。
2. 選択中の日付、現在時刻から1時間の正確な予定フォームを開く。
3. タイトル、日付、種別、必要な時間情報を入力して保存する。
4. 成功時だけフォームを閉じ、カレンダーを再読込する。

### 3.2 2日ビューからの素早い作成

1. タイムライン列をダブルタップする。
2. タップした列の日付と、タップ位置に最も近い時刻を`HH:00`へ丸めて新規フォームを開く。
3. 画面上部の既存「追加」ボタンは廃止する。

時刻は00:00〜23:00に収め、23時台のダブルタップも23:00として扱う。終了時刻が開始時刻より前の場合は、終了を翌日として扱う。開始・終了が同じ時刻の場合は24時間予定を作らず、入力エラーにする。

### 3.3 編集・削除

1. 2日ビューの予定ブロック、または月ビューの選択日の予定一覧をタップする。
2. 対象予定を読み込んだ編集フォームを開く。
3. 保存は更新、削除はネイティブ確認ダイアログでの明示的な確認後に実行する。
4. 更新・削除が成功した場合だけカレンダーへ戻り、表示を再読込する。

## 4. フォームと表示の境界

### 4.1 画面・route

- `src/app/events/new.tsx`は新規作成用の初期値と依存を組み立てる。
- `src/app/events/[id].tsx`は編集対象IDと依存を組み立てる。
- 両routeは共通の`EventEditorScreen`へ表示用stateとcallbackだけを渡す。
- どちらもStack modalとして表示する。

新規routeのsearch parameterは`date`、`startTime`、`temporalType`を使う。編集routeは動的segmentの`id`を使う。

### 4.2 feature hook

`useEventEditor`が次を担当する。

- 既定カレンダー、有効な日内時間表現、編集対象予定の読み込み
- 新規予定の初期値と編集予定のフォーム値への変換
- タイトル、日付、種別、開始時刻、終了時刻、時間表現の状態管理
- 入力検証、作成、更新、削除、再試行、保存中の二重操作防止

UIコンポーネントはRepository、SQLite、Expo Router、端末APIへ直接依存しない。

### 4.3 表示部品

- `EventEditorScreen`: ヘッダー、フォーム状態、保存・削除・キャンセルの表示組み立て
- `EventTypePicker`: 正確・終日・ざっくりの選択
- `EventDateTimeFields`: 日付、開始時刻、終了時刻を表示する。Expo SDK 57の`@expo/ui/community/datetime-picker`をこの部品だけで利用する
- `TemporalDefinitionPicker`: 既存部品を再利用する
- `DeleteEventButton`: 編集時だけ表示し、削除確認のcallbackを呼ぶ

常設追加ボタンはカレンダー画面のみで使うため、`features/calendar/components`に置く。

## 5. ドメインと永続化

### 5.1 正確な予定

SQLiteの既存`events`テーブルの`start_time`と`duration_minutes`を利用する。新規列・migrationは不要である。

正確な予定はフォームで`startTime`と`endTime`を持ち、保存直前に`durationMinutes = endTime - startTime`へ変換する。

- `startTime`と`endTime`は`HH:mm`形式である
- `endTime`が`startTime`より後なら同日、前なら翌日である
- 差分は1〜1,439分である
- 保存された`duration_minutes`がこの範囲なら、編集時に終了時刻へ戻せる

既存の正確な予定に保存済みの10、15、30、60分以外の固定分数も、同じ`fixed` durationとして読み書きできるようにする。`instant`と`undetermined`は既存データを壊さず読み込めるが、このフォームの正確な時刻入力では作成しない。

### 5.2 種別切替

- 正確: 日付、開始、終了を表示して保存する
- 終日: 日付だけを表示して保存する
- ざっくり: 日付と時間表現を表示して保存する

切替で現在入力中のタイトルと日付は保持する。種別ごとの入力は、切り替え前に有効な値を持つ場合だけ保持して戻せるようにする。保存時は選択中種別に不要な値をイベントへ含めない。

### 5.3 Repository

既存`EventRepository`の`create`、`getById`、`update`、`delete`を利用する。すべてのSQLite実装は引き続きバインドパラメータを使う。

## 6. カレンダー連携

- `CalendarScreen`へ新規作成と編集開始のcallbackを渡す。
- 月ビューの選択日予定一覧は`Pressable`で編集callbackへ予定IDを渡す。
- 2日ビューの予定ブロックは`Pressable`で編集callbackへ予定IDを渡す。
- 2日ビューのタイムライン列では、単一タップを予定操作に使わず、ダブルタップだけを新規作成に使う。
- ダブルタップの時刻解決は、タイムラインのY座標と既存scaleから分を算出し、最も近い時間へ丸める純粋関数にする。
- 表示対象期間を取得するときは必ず前日から読み込み、翌日へ継続する正確な予定を2日・月ビューの対象日で表示できるようにする。

## 7. エラー・アクセシビリティ

- 読み込み失敗時は再試行ボタンを表示する。
- 保存・削除失敗時はフォームを維持し、理由を安全なユーザー向け文言で表示する。
- 保存・削除中は重複操作、キャンセル、戻るジェスチャーを無効にする。
- 操作要素は44pt以上のタップ領域と、内容を説明するアクセシビリティラベルを持つ。
- 削除確認の操作には「削除」と対象タイトルを含める。

## 8. 受け入れ条件

- 右下の常設追加ボタンから、選択日・現在時刻から1時間の正確な予定を作成できる。
- 2日ビューの上部に予定追加ボタンが表示されない。
- 2日ビューのタイムラインをダブルタップすると、該当日・最も近い`HH:00`を初期値に作成フォームが開く。
- 正確な予定で開始時刻と終了時刻を任意に選び、終了が開始より前なら翌日へ継続する予定として保存できる。開始・終了が同じ時刻なら保存できない。
- 既存予定をタップしてタイトル、日付、種別、時間情報を変更できる。
- 編集画面から確認付きで削除でき、成功後にカレンダーから消える。
- 保存・削除の失敗ではフォーム入力を失わない。
- 既存のざっくり予定作成は維持される。
- 型チェック、lint、全テスト、iOS/Android exportが成功する。

## 9. 検証範囲

テスト名、`describe`、`test`、`it`、新規コメントは日本語で記述する。実装は各振る舞いについて失敗するテストを先に書き、失敗理由を確認してから最小実装を追加する。

自動テストでは、任意終了時刻、種別切替、保存・更新・削除、失敗時の入力保持、イベントタップ、常設追加、ダブルタップ時刻解決を検証する。ネイティブピッカーのOS固有の見た目と実機ジェスチャーは、iOS/Android実機で確認できるまで未検証として扱う。
