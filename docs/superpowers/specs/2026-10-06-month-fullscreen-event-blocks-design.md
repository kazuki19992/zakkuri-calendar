# 月ビューの全画面予定ブロック・1日ビュー導線設計

## 1. 目的

Issue #39として、月ビューを選択日の予定一覧を常設しない全画面グリッドへ変更する。利用者が月全体の予定密度と複数日にまたがる予定を一目で把握でき、日付・余白・「他N件」から仮の1日ビューへ進める状態を作る。

予定ブロックは予定色、タイトル、時間表現、形状、読み上げ情報を併用する。色だけで予定種別や継続を表現しない。

## 2. 範囲

### 対象

- 月カレンダーを画面の主要領域いっぱいに表示する。
- 各日セルに予定ブロックを最大3レーン表示する。
- 複数日予定を週行単位の連続帯として表示する。
- 日付数字・セルの余白・「他N件」から仮の1日ビューを開く。
- 月内の予定ブロックから既存の予定編集画面を開く。
- iOSで日付セルを長押しした際に、Expo Routerのネイティブ`Link.Preview`で1日ビューを表示する。

### 対象外

- 週・1日・3日ビューを完成したカレンダー体験へ拡張すること。今回の1日ビューは一覧だけの仮画面とする。
- Androidでの長押しプレビュー、独自の長押しモーダル、OS標準プレビューの再現。
- 月表示位置・スクロール位置の永続化。
- SQLite schema、Repository契約、予定データ形式の変更。
- 2日ビューの表示や操作の変更。

## 3. 利用者操作

| 操作対象 | 通常タップ | iOS長押し |
| --- | --- | --- |
| 日付数字・セル余白 | 対象日の1日ビューを開く | 1日ビューのネイティブプレビュー |
| `他N件` | 対象日の1日ビューを開く | 通常タップと同じ導線でよい |
| 予定ブロック | 該当予定の編集画面を開く | プレビューを開始せず、既存の編集操作を優先 |

日付を開く前に月ビューの`selectedDate`も対象日へ同期する。戻った後に選択表示を維持し、現在の月ビューの選択日・アクセシビリティ情報を失わない。

AndroidとWebでは、日付数字・セル余白・`他N件`の通常タップだけを提供する。iOS専用のプレビューは、Expo Router SDK 57で利用できる`Link.Preview`を使う。プレビュー内では`useIsPreview()`を参照し、編集遷移、追加、通知などの副作用を起こさない。

## 4. 表示モデルと並び順

### 4.1 月日と週行

`MonthDayViewModel`は日付ヘッダー用の状態（今日、選択、祝日、月外日、読み上げ）を維持する。予定表示は日単位の`hasEvents`や点表示ではなく、月全体から作る`MonthWeekViewModel`と`MonthEventSegmentViewModel`へ分離する。

`MonthEventSegmentViewModel`は、週行に描画できる値だけを持つ。

- stable display key、編集先の`eventId`、繰り返し発生回の`originalOccurrenceDate`
- 週行番号、開始曜日、横幅（日数）、開始前・終了後へ継続するか
- 最大3本のレーン番号
- 解決済み`colorId`、タイトル、時間表現、読み上げラベル
- 形状（開始、途中、終了、単日）と予定種別（複数日、終日、当日）

`EventOccurrence`を対象月グリッドの日付範囲と交差する週ごとの区間へ切り出す。日付境界の比較は既存の`occursOnCalendarDate`と`date-fns`境界を使い、固定ミリ秒の加減算をしない。

### 4.2 優先度とあふれ

各週行では次の順で候補を並べ、空いている最初のレーンへ貪欲に配置する。同じレーンでは区間が重ならない。

1. 2日以上にまたがる予定
2. 1日の終日予定
3. その日の時刻指定・ざっくり予定

同一優先度では、表示週内の開始日、開始時刻または時間表現の安定順、タイトル、表示keyで決定する。レーンは3本までとし、配置できない予定はその予定が該当する日ごとのhidden countへ加える。セル末尾の`他N件`は、当日の隠れ予定が1件以上ある場合だけ表示する。

この方式は、複数日帯を同じ週内で同一レーンに保つ。ある日の単発予定だけが帯の間へ割り込んで、継続予定が分断されることを防ぐ。

### 4.3 帯の見た目

複数日予定は週ごとに1つの絶対配置帯として描画する。開始日は左を丸め、終了日は右を丸め、中間日は角を丸めない。週外から続く区間は左端を、次週へ続く区間は右端を淡くフェードさせ、週をまたいでも継続中であることを示す。

終日・時刻指定・ざっくり予定の単日ブロックはセル幅内に表示する。予定自身の固定`colorId`を優先し、未設定時だけカレンダー既定色へfallbackする。祝日は予定ブロックとして混在させず、既存の祝日名・祝日色・読み上げを日付ヘッダーに維持する。

すべての予定ブロックは`時間表現 タイトル`を1行で表示する。文字が長い場合は末尾を省略しても、読み上げラベルにはタイトル、時間表現、複数日であること、繰り返し予定・個別変更済みの既存情報を保持する。

## 5. レイアウトとアクセシビリティ

月ビューでは`CalendarTopBar`の下からセーフエリアとFABの必要領域を除いた残りを`MonthGrid`へ割り当てる。曜日見出しと6週間を固定して、選択日の`SelectedDayAgenda`は月モードで描画しない。月移動の既存横スワイプはグリッド全体で維持する。

日付ヘッダーは日付数字、今日、選択、月外日、土日祝を現在のsemantic tokenと形状で示す。予定レーンは日付数字の下に置く。月外日の予定は月内日と同じ情報を保ちつつ、既存の弱い表示を維持する。

小画面・文字拡大では、月の高さを増やして別一覧を表示しない。予定は1行、最大3レーン、`他N件`へ収める。文字が狭い場合も時間表現を先頭に残し、アクセシビリティラベルには省略前の情報を渡す。各日付導線、`他N件`、予定ブロックは44pt以上の実効操作領域を確保する。予定ブロックの操作領域を拡張する際も、隣接セルの導線を覆わない。

通常タップと長押しが競合しないよう、日付導線は予定ブロックの外側だけに置く。予定ブロックは親リンクの子にせず、独立した`Pressable`として編集callbackを受け取る。

## 6. 1日ビュー（仮）とルーティング

`src/app/calendar/day/[date].tsx`を薄いExpo Router routeとして追加し、`src/features/calendar/screens/day-calendar-screen.tsx`へ依存を渡す。route parameterは`YYYY-MM-DD`だけを受け入れ、不正値は安全なエラー表示と戻る導線を出す。

`useDayCalendar`は対象日だけのschedule、時間表現定義、祝日情報をRepository境界から読み、`createAgendaItems`を再利用して表示用一覧を作る。画面は日付見出し、祝日名、予定一覧、空状態、読込中、読込失敗と再試行だけを提供する。予定をタップすると、繰り返し発生回の`originalOccurrenceDate`を保って既存編集routeへ進む。

1日ビューは今後の専用タイムラインへ置き換え可能なscreen境界とし、月ビューからSQLiteやRepositoryを直接読ませない。iOSプレビュー時はこの同じrouteを使い、プレビュー専用の別データ形式・別画面を作らない。

## 7. コンポーネント境界

```text
CalendarScreen
  -> MonthGrid (全画面の週行・予定segment)
      -> MonthDayHeader / DayViewLink
      -> MonthWeekEventLayer
          -> MonthEventBlock
  -> CalendarAddEventButton

src/app/calendar/day/[date].tsx
  -> DayCalendarScreen
      -> useDayCalendar
      -> DayAgendaList
```

- `src/domain/calendar`: 日付範囲、週境界、発生回の既存計算だけを担う。
- `src/features/calendar/month-view-model.ts`: occurrenceから週行segment、レーン、hidden countを作る純粋関数を担う。
- `src/features/calendar/components`: 表示済みViewModel、callback、iOSの`Link.Preview`だけを扱う。SQLite、holiday library、期間解決規則へ直接アクセスしない。
- `src/features/calendar/hooks`: 月表示の選択同期、1日ビューの読込・再試行・古い非同期結果の破棄を担う。
- `src/app`: Routerのparam検証、Repository依存のcomposition、画面配置だけを担う。

## 8. エラー処理

- 月の期間読込失敗は既存の`CalendarLoadState`と再試行を維持し、前の月内容を新しい空グリッドで置き換えない。
- 1日ビューの読込失敗は月ビューへ影響させず、1日画面内で「予定を読み込めませんでした」と再試行を示す。
- iOSプレビューが利用できないOS・環境では通常リンクとして開ければよく、独自fallback UIは作らない。
- 予定block・1日ビューへの編集遷移に失敗した場合は既存routeのエラー表示へ委ね、表示用の予定データをログへ出さない。

## 9. テスト

- presentation: 月グリッド範囲、週をまたぐsegment、開始・途中・終了形状、色fallback、複数日 > 終日 > 当日予定の優先順、同一レーン非重複、各日のhidden count、繰り返し発生回の編集identity。
- components: 全画面6週グリッド、日付数字・セル余白・`他N件`の1日ビュー導線、予定blockの編集導線、祝日・今日・選択日・月外日、3レーン上限、帯の連続表示と読み上げ。
- route / hook: 不正date parameter、読込中、空状態、読込失敗・再試行、発生回の編集遷移、unmount後または新しい日付への古い読込結果の破棄。
- platform: iOSで`Link.Preview`を設定し、Android / Webでは通常遷移を維持することを分岐テストする。
- regression: 既存の月移動、横スワイプ、date picker、2日ビュー、選択日更新を維持する。
- 全体: typecheck、lint、全テスト、`git diff --check`。実機ではiOSの長押しプレビュー、Android通常遷移、ライト・ダーク、小画面、文字拡大、VoiceOver / TalkBackを確認する。

## 10. 将来拡張

1日ビューの一覧は、将来の時間軸・予定の並べ替え・日内追加操作へ置換できる。月のsegment ViewModelは週・複数日帯に必要な最小値だけを持ち、月外の週ビューへ先行して一般化しない。
