# カレンダーの週開始曜日設定（Issue #10）

状態: 設計承認済み・実装済み。typecheck、lint、67 suites / 623 tests、iOS／Android export成功。実機未確認。

## 目的と合意事項

月カレンダーを習慣に合わせて月曜始まり／日曜始まりへ切り替えられるようにする。初期値は月曜日とする。

ユーザーとの合意により、この設定はカレンダーの表示順へ適用する。「今週前半＝月〜水」「今週末＝土〜日」など、週単位のざっくり表現は引き続き月曜を基準に解決する。保存済み予定の開始日・終了日・解決contextは変更しない。「今週中の締切」の設定も独立して維持する。

## 対象範囲

- 設定画面に「カレンダー」セクションと「週の開始曜日」を追加する。
- 月曜／日曜を既存の共通 `SingleSelectSheet` から単一選択する。
- 月ビュー本体、ヘッダーから開く月の日付選択、両者の曜日見出し・日付配置・予定帯・祝日取得範囲へ適用する。
- 2日ビューと現在の1日ビューは日付を維持する。月移動は引き続き暦月単位、月グリッドは6週間固定とする。
- 週ビューは未実装のため追加しない。将来の週ビューは同じ設定値を表示境界として利用する。

## 対象外

週のざっくり表現、繰り返し規則の月曜基準、締切曜日、予定データ、祝日計算ルール、予定編集のOS標準日付ピッカーは変更しない。新しい依存は追加しない。

## 設定値と永続化

- キー: `calendar_week_starts_on`
- domain型: 既存の `WeekStartsOn`（`0 | 1`、日曜=0、月曜=1）を利用する。
- 既定値: `1`。
- 保存形式: `app_settings.value_json` にJSON数値を保存する。
- 欠損、不正JSON、文字列、boolean、0/1以外は月曜へfallbackする。DBアクセス自体の失敗は設定読込エラーとして扱う。
- `SettingsRepository` に型付きgetter/setterを追加する。setterはruntime値を検証し、bound parameterによる既存UPSERTで保存する。
- 既存の `app_settings` を使用するため列追加・schema version変更・seed追加は不要。未保存は既定値で解決する。

## 画面と操作

表示例は「カレンダー / 週の開始曜日　月曜日」。選択シートは月曜日、日曜日の順とし、選択値には既存コンポーネントのチェック表示と `accessibilityState` を使う。操作領域は44pt以上を維持する。

補足文: 「カレンダーの表示順に適用されます。『今週前半』などの期間や、保存済みの予定は変わりません。」

設定は保存成功後に選択値を更新する。保存中は同じ設定の再操作を防ぎ、同じ値の再選択は書き込まない。保存失敗では以前の選択を維持し、項目付近へ再試行可能な文言を表示する。読込失敗時は選択を無効化し「再読み込み」を提供する。既存の締切設定の状態・エラーとは独立させる。

未完了の非同期処理はunmount後の画面を更新しない。多重保存はhandler入口の同期ガードで抑止する。

## カレンダーへの反映

実装側の判断として、`useCalendarView` が設定値と対象期間snapshotを一つの表示状態として管理する。routeの `weekStartsOn: 1` 固定入力を除去する。

初回読込では週開始設定を取得してから、その値を使う月グリッド全体の予定・祝日snapshotを取得する。設定読込が失敗した場合はカレンダーの読込エラーとして再試行可能にし、既定値を保存済み設定として扱わない。

設定保存成功時には既存 `CalendarRefreshContext.notifyChanged()` を呼ぶ。設定画面から戻るときの再マウント有無に依存せず、refresh時に週開始設定を再取得する。通知は設定画面が閉じられても保存成功に対して行い、画面state更新だけをmounted guardで制限する。

設定値が変わった場合は現在の表示月・選択日・2日ビューのanchor・view modeを維持して対象snapshotを再取得する。新しい曜日配列だけを古いsnapshotへ先行適用しない。取得成功時に設定値とsnapshotを同時反映し、失敗時は旧表示を維持して期間読込エラーと再試行を示す。後発リクエストをrequest generationで優先し、古い読込完了を採用しない。

ヘッダーの日付選択用月カレンダーにも同じ表示設定を渡す。開いているpickerのsnapshotは設定変更時に再取得・無効化し、古い曜日順の結果を後から反映しない。予定取得範囲・祝日対象月は必ず反映先の週開始値から算出する。

## 曜日見出しと予定帯

`MonthGrid` の月曜固定配列を除去し、同じ週開始値から見出し順と日付グリッドを作る。土日色は列番号ではなく実曜日に従う。日曜始まりでは先頭が日曜色、末尾が土曜色になる。読み上げも実曜日に一致させる。

予定帯は日付グリッドに対する配列位置を使って配置し、曜日番号を列番号として扱わない。複数週のざっくり予定のグラデーションは保存期間全体を基準とする既存計算を維持する。

## 検証と受け入れ条件

- 欠損・不正値のfallback、0/1の保存再読込、不正setter値の拒否をRepositoryテストで確認する。
- 設定hookの読込・再試行、保存成功／失敗、連続操作、unmount中の保存完了を確認する。
- 初回と設定復帰時に、曜日順・予定取得範囲・祝日範囲が一致することをhookテストで確認する。
- 新snapshot失敗時は旧曜日順と旧snapshotを維持し、retry成功で同時切替する。遅い旧リクエストが新設定を戻さない。
- 日曜始まりの月初・月末・年境界・閏年、先頭／末尾の土日色と読み上げ、6週間固定を確認する。
- 本体とヘッダーの月pickerに同じ設定が適用され、複数日帯・他N件・グラデーションが正しい列へ表示される。
- 同じ参照日・定義から解決する週単位予定の期間が表示設定によらず一致する。繰り返し発生回と保存済みevent行を変更しない。
- `npm run typecheck`、`npm run lint`、`npm test -- --runInBand`、`git diff --check`を実施する。
- 実機では設定変更→戻る→再起動、ライト／ダーク、文字拡大、VoiceOver／TalkBack、月picker、月跨ぎの帯を確認する。自動検証と実機確認は区別して報告する。
