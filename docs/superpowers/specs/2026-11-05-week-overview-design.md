# 週全体を見渡す7日時間軸ビュー

状態: 設計案。ユーザーレビュー待ち。実装未着手。

## 1. 目的と合意

ユーザーの目的は「週の様子を一覧で見たい」であり、詳細の判断は実装側へ委ねられた。週全体の予定の入り方、空いている日・時間帯、複数日にわたるざっくり期間を同じ画面で見渡せるようにする。

以下の7列表示、密集時の省略、操作の詳細は実装側の提案である。現時点で個別にユーザー承認された内容とは扱わない。本書全体のレビュー後に実装計画へ進む。

対応Issueは [#52](https://github.com/kazuki19992/zakkuri-calendar/issues/52)、親は [#1](https://github.com/kazuki19992/zakkuri-calendar/issues/1)。MVP設計の「日・週・月」の未実装部分を扱い、既存の1日・2日・月表示を維持する。

## 2. 表示方式の判断

候補は、7日を同時表示する時間軸、数日ずつ横スクロールする時間軸、曜日ごとの予定一覧である。今回は7日同時表示の時間軸を採用する。

数日ずつの方式は予定名を読みやすいが、週全体を見るために移動が必要になり、既存2日表示と役割が近い。曜日別一覧は予定名を読みやすいが、日ごとの空き時間を比べにくい。7列の時間軸は詳細な文字に限界があるため、密集状態を隠さず件数で補い、詳細を既存1日表示へ渡す。

## 3. 対象と対象外

対象:

- サイドメニューの週モードと最後の表示モードの復元。
- 7日分の見出し・終日欄・共有24時間軸、複数日予定とグラデーション。
- 前週／翌週、今日、日付picker、1日表示への切替、予定の作成・編集。
- 密集時の表示制限、読み込み・保存失敗、アクセシビリティ。

対象外:

- 横スクロールで数日だけを見せる別の週モード、3日表示、横方向ピンチ。
- 週ビュー独自のドラッグ移動・リサイズ・長押し作成・OSプレビュー。
- 表示日や倍率の永続化、通知発火、メモUI変更、新しいDB列。
- 既存1日・2日表示の密集レイアウトの作り直し。

## 4. モードと週の範囲

`CalendarViewMode` に `week` を加え、メニューを「1日／2日／週／月」の順とする。初回既定値は従来の `twoDay`。既存 `last_calendar_view_mode` に `week` を保存し、parser以外のschema変更は行わない。

選択日を含む暦週の7日間を表示する。週の開始は既存 `calendar_week_starts_on` の月曜／日曜設定へ従う。表示用の週範囲と、相対予定・繰り返し規則の基準週は別のルールであり、今回後者を変更しない。

- 週へ切替: 現在の選択日を維持し、その日を含む週を開く。
- 前週／翌週: 選択日とanchorを暦日で7日ずらす。表示上の曜日位置も維持する。
- 今日: 端末の今日を選択し、その週を開く。
- 日付picker: 選んだ日を含む週へ移動し、週モードを維持する。
- 週から他モード: 現在の選択日を使う。週初日に自動で置き換えない。
- 再起動: 保存済みweekなら今日を含む週から開く。
- 週開始設定の変更: 選択日を維持して週の範囲を再計算する。保存済み予定の日時・解決contextは変更しない。

取得に成功した週範囲・選択日・snapshotを同時に反映する。取得失敗では元の表示を維持し、再読み込みを用意する。モードの保存はsnapshot成功後に行い、保存失敗は表示と独立したエラーにする。保存中のURL要求を取りこぼさない既存の待機処理を維持する。

## 5. 画面構成

既存トップバー、ハンバーガーメニュー、今日、月picker、FABを使う。本文は日付見出し、終日欄、24時間軸、前週／翌週ボタンの順とする。通常表示に横スクロールを置かず、時刻欄48ptを除いた横幅を7等分する。日付見出しと時間軸の列幅は同一とし、minWidthによって画面外へはみ出させない。

トップバーは選択日の月・年を既存規則で示し、その下に週範囲を別途表示する。同一年は `11月2日〜11月8日`、年跨ぎは `2026年12月28日〜2027年1月3日` とする。週範囲は文字拡大時に折り返せるようにする。

日付見出しは曜日と日付数字を表示し、今日・土日祝・選択日を既存semantic tokenと読み上げ状態で区別する。祝日名は終日欄と見出しのaccessibilityLabelへ含め、見出しの文字数によってdividerの高さを変えない。

時間軸は標準時に残り高さへ0〜24時をfitさせ、縦方向のピンチで拡大する。下限はfit、上限は既存等倍（fitが等倍以上ならfit）。倍率による1／2時間ごとのラベルと数字のフェード、現在時刻と重なる定時ラベルの非表示、罫線の背後レイヤーを共用する。日付をまたいだ復帰でも今日判定を更新する。

## 6. 予定表示と密集状態

### 6.1 終日欄

複数日の予定は日付列をまたぐ一本の帯とし、週境界ではクリップする。範囲のグラデーションは保存済みの開始・終了とフェード比率から表示部分を切り出し、週ごとに濃淡をリセットしない。「今週中」は開始から締切へ濃くなる既存定義を使う。日内fuzzy・未定時間の縦グラデーションも維持する。

優先度は、複数日予定、祝日、そのほかの単日終日・未解決予定の順。同優先度は期間の長い順、開始日、安定した発生回keyで決定し、再描画のたびに入れ替えない。

終日欄は最大2レーン（1レーン44pt）。本文の実測高の3分の1以下で、収まる整数レーン数へ減らす。2レーンが収まらなければ1、1レーンも収まらなければ0とする。空欄時は従来と同程度の最小高とし、空の88ptを確保しない。文字拡大時も領域を際限なく伸ばさず、全文は1日表示と読み上げから確認できるようにする。

帯のタイトル・時間表現は省略可能だが、選択色・ざっくりを示す破線・期間継続の角丸・読み上げを維持する。祝日は専用色と非編集の項目にする。

### 6.2 時刻付き予定

日ごとの時刻解決、前日からの継続、重複対象、選択色と読み上げは既存表示モデルを使う。週用の表示レイアウトでは、実際の縮尺と最小表示高36pt、24時付近の位置補正を反映した矩形同士の衝突を計算する。時刻だけで重複判定すると、縮小後に最小高を持つ予定同士が重なるためである。

各日の衝突グループは最大2レーンとし、それを超える項目は省略件数へ回す。細すぎる帯を避けるため、上限は `min(2, max(1, floor(実測日列幅 / 36pt)))` とする。通常のスマホ縦画面では1レーン、十分に広い画面では最大2レーンになる。36ptは週用の表示設定値として一箇所に置き、後から調整可能にする。

表示順は補正後top、元の開始分、発生回keyの順で安定させる。上から順に空いているレーンへ割り当て、上限のレーンがすべて埋まっている場合にその項目を省略する。省略した項目はレーンを占有しない。グループ内で実際に使うレーン数により1列または2列へ均等分割する。

表示する予定はタイトルと時間表現を各1行で省略表示する。文字を極端に縮小して全情報を押し込まない。予定を実際の開始時刻と異なる時間へ移動させて文字を読む場所を作ることもしない。最小高と下端の補正は、週用の衝突計算と描画で必ず同じ純粋関数を使う。

### 6.3 省略件数

各日の見出しに、終日欄と時間軸で省略した項目をまとめて `他N件` と示す。同じ日で同じ発生回を二重計上しない。非表示カレンダーの予定は数えず、終日欄から省略した祝日は1項目として数える。週全体の合計ではなく、その日の1日表示で確認できる項目の件数である。

表示可能な項目がない日を、隠れた予定のある日と同じ空欄にしない。見出しの読み上げには日付、祝日、今日、予定件数、省略件数を含める。画面に収まらないタイトルや極端な重複でも、日付／他N件から全項目に到達できる。

## 7. 操作

- 日付見出し・他N件: 対象日の1日モードへ原子的に切り替える。戻るヘッダーや週へ戻す履歴を作らない。週へ戻す場合はサイドメニューを使う。
- 予定ブロック: 既存同様に編集を開く。元シリーズIDと元発生日を引き継ぎ、繰り返し例外を別予定として誤編集しない。
- FAB: 選択日を初期値とする通常フォームを開く。週の余白を単にタップして選択日を変える操作は追加しない。
- 空き時間のダブルタップ: 対象列の日付と最も近いHH:00で正確な予定フォームを開く。日付の逆算は実測列幅を使い、時刻欄や見出しでは作成しない。
- 左右スワイプ・前後ボタン: 暦週1週ずつ移動する。2日表示のような1日ずつの移動にはしない。
- ピンチ: 縦倍率の変更。2本指操作へ変わったスワイプは確定せず、予定追加も抑止する。

日付や他N件の切替に失敗した場合も週表示を維持する。予定編集・設定・フォームから戻った場合は週と選択日を保持し、既存のrefreshRevisionで再取得する。

## 8. 取得範囲と状態の境界

週の範囲を返す純粋関数をdomainの既存日付計算境界へ追加する。固定ミリ秒加算を使わず、週開始設定と暦日の加算で年月境界・閏年・夏時間を扱う。weekを誤って既存非month分岐の2日範囲へ流さないよう、取得範囲・初回復元・移動・picker・祝日取得・表示モデルの分岐をすべて確認する。

横移動中も取得済みの内容を見せるため、前週・表示週・翌週の計21日分を用意する。日跨ぎfuzzyのため検索開始はその先頭のさらに前日まで広げる。予定Repositoryの期間交差と繰り返し展開を維持し、非表示設定は表示モデルへ渡す前に適用する。祝日取得は21日が属する各月を重複なく扱い、無効／未対応を区別する。

週モデルはsnapshotの週開始値から組み立てる。設定の再取得中に旧snapshotへ新しい曜日順だけを適用しない。設定変更やrefreshと週移動の取得が競合した場合も、最新要求だけを反映する。1日へのURL要求・モード保存中の待機・unmount後の完了抑止は既存の仕組みを維持する。

carouselは表示7列、前後各7列のバッファとし、1回の移動量は7列幅にする。表示列数と移動日数を別々に扱い、既定の1日／2日表示は1列移動を維持する。日付見出し・終日帯・時間軸は同じtranslateXを使う。移動後の基準位置同期、失敗時の復帰、同時操作の抑止、Reduce Motionは既存方式を踏襲する。

## 9. アクセシビリティと小画面

画面全体、通常ボタンと日付見出しは高さ44pt以上にする。7日同時表示では小画面の列幅が44pt未満になり、重複予定はさらに狭くなる。ここをminWidthや隣列にはみ出すhitSlopで解消すると7列表示や誤タップ防止を壊すため、個別ブロックの幅44ptは保証しない。

その代わり日付見出しと他N件を同じ1日表示への入口とし、VoiceOver／TalkBackで各日と予定の完全な情報をたどれるようにする。欄の外へ操作領域を重ねず、同日の詳細操作は1日表示から行える。日付見出しは予定全体を包むaccessible親にせず、子の予定ボタンを読み上げから隠さない。

省略情報は文字を拡大しても失われないよう保持し、週モードでの幅不足とデータ欠落を区別する。文字拡大時は週範囲の折返し、見出しの必要高、下部操作の高を計測し直し、残りの時間軸へfitさせる。前後週のバッファは読み上げ対象から除き、表示7日だけを操作対象にする。ライト／ダーク、色以外の状態表示、倍率のadjustable actionsを維持する。

## 10. 実装境界

- domain: weekモードparser、週範囲・暦週移動。保存済み予定や繰り返し規則の意味は変えない。
- feature純粋関数: 7日モデル、表示縮尺での衝突レーン、省略件数、元の期間に基づく帯のクリップ。
- feature hook: snapshot、モード復元、週移動とcarousel、保存・取得の競合調整。
- feature UI: 週の見出し、コンパクトな予定ブロック、終日帯、既存トップバーと1日表示への接続。
- route: 新しい週専用routeは作らず、main内のモードとして組み立てる。

時間軸・罫線・現在時刻・zoom・元の色とグラデーションは実際に共用する部分だけを拡張する。週用の衝突レイアウトを既存1日／2日へ一律適用しない。calendar専用UIはfeature内に置き、他画面にも共用するUIだけを `src/shared/components` へ置く。コンポーネント名の変更やファイル分割の具体形は実装者へ委ねる。

新しいカレンダーライブラリ、native依存、global store、DB migrationは追加しない。

- 月曜／日曜の週範囲、年跨ぎ、閏年、DST、週開始設定変更と選択日の維持。

- 複数日帯、週をまたいでも連続するフェード、祝日専用色と無効／未対応。
- 320／390／430ptで7列が収まり、列幅・スワイプ量が一致すること。
