# 予定画面に埋め込む書式付きメモ

## 状態と根拠

Issue #62。2026-11-17に本書全体の承認を受け、実装を開始する。

- ユーザー確認済み: メモ専用の「完了・キャンセル」をなくし、予定全体の「保存・キャンセル」で確定・破棄する。予定保存まではインメモリとする。
- 全体承認により「最初から本文を表示し、その場で編集する」方式を採用する。寸法とtimeoutは担当の提案値として具体化する。
- 現行の全画面メモ設計: `2026-10-02-rich-text-event-notes-design.md`。書式・domain文書・変換・外部通信制限は引き継ぐ。

## 目的と範囲

予定の日時や場所と同じ画面でメモを書き、チェック項目や書式を操作できるようにする。Markdownの知識を要求しない。

太字・斜体・箇条書き・番号付きリスト・チェックリスト・HTTP/HTTPSの自動リンクを維持する。通常予定、繰り返しの元予定・各回・これ以降・全体変更で、同じメモ編集と保存境界を使う。

画像・新書式・同期・共同編集・アプリ終了後の未保存メモ復元は今回の対象外。DBの文書形式とschema version 7は維持し、新しいnative依存は追加しない。

## 表示と操作

予定フォームの既存「メモ」セクションへ編集本体を置く。空なら「メモを追加」のplaceholder、既存メモがあれば対応書式とチェック状態を表示する。起動・再表示で自動フォーカスせず、本文をタップした時だけ編集を始める。

本文領域は短文で数行、内容が増えると上限まで広がり、以降は本文内をスクロールする。担当提案の初期寸法は最小120pt、通常上限320pt。キーボード・Safe Area・ヘッダー・ツールバーを除いた利用可能高さが小さい場合は上限を縮め、文字拡大時も少なくとも入力行とカーソルへ到達できるようにする。具体的な計算式は実装計画で決め、最小値を理由に小画面からはみ出させない。

- 予定全体のスクロールとメモ内部のスクロールを区別し、本文外からはフォームを移動できる。
- 編集を開始したら本文領域をキーボード上へ移し、長文ではカーソル位置を本文内部で追従させる。高さ更新は本文寸法が変わった場合だけ反映する。
- メモ編集中は画面下部・キーボード直上に既存の書式ツールバーを表示する。ハードウェアキーボードではメモにフォーカスがある間、画面下部へ表示する。別項目へ移ると隠す。
- 書式ボタンを押しても選択範囲・カーソルを維持し、本文へ編集を戻す。ツールバー自身へのフォーカス移動を「編集終了」と誤判定しない。
- キーボードを閉じても本文・選択状態・未保存変更は保持する。Androidの最初の戻る操作はキーボードを閉じる。
- チェック操作は本文の変更として扱う。リンクは既存の「リンクを開く」操作から安全なURLだけを外部ブラウザへ渡す。タップからWebViewを直接遷移させない。
- ざっくり／きっちり切替の既存横スライドにメモも含めるが、DOM編集セッションを作り直さない。初期文書を毎回propsから再投入しない。

## 保存・取消と最新本文の取得

メモ専用の確定操作は設けない。フォームで入力したメモは、予定を保存するまで端末内のメモリにだけ保持する。

予定ヘッダーの保存から次を一連の操作として扱う。

1. 同期的な操作ロックを取り、保存連打、取消・戻る・別の保存範囲操作との競合を防ぐ。
2. DOMが準備済みなら、未変更に見える場合も現在の文書を要求する。nativeに最後に届いたstateだけを保存しない。
3. DOMは要求処理の同じ実行単位で入力を止め、最新のTiptap JSONを既存adapterでdomain文書へ変換する。IMEの未確定入力がある場合は確定後の文書を返し、確定できなければ保存を続けない。
4. 要求ID・セッションIDを含む応答をnativeで検証・正規化する。受け取った文書をその保存処理へ直接渡し、setState直後の古いclosureから保存しない。
5. 他の項目・通知を検証し、通常予定は既存Repositoryで保存する。繰り返しはこの文書を含むpending aggregateを作り、既存の範囲選択・例外リセット確認へ進む。
6. 成功後にカレンダーを更新して閉じる。入力エラー・DB失敗では最新文書と他の入力を保持して編集へ戻す。範囲選択の取消も入力を保持する。

DOM文書の要求は1件だけ処理し、要求中の入力停止をDOM側でも保証する。要求のtimeout（担当提案は5秒）・失敗・離脱後はロックとpending要求を必ず解放し、遅れた別セッションの応答を無視する。繰り返し範囲の選択中は、確認中の文書が裏で変わらないようにする。

タイトルや日時などの検証で保存を止めても、取得できたメモはインメモリdraftへ保持する。単回だけを保存した場合のnotes mask・他の回の継承は既存の仕様に従う。

予定のキャンセル・戻るではメモを保存しない。メモに変更がある場合は、予定全体から離れる前に「変更を破棄しますか？」を一度だけ確認し、継続なら入力を保持する。メモだけの別の取消確認は重ねない。未変更判定も遅延stateだけに頼らず、準備済みDOMがある場合は最新文書を確認する。取得不能なら変更不明として破棄を明示確認する。削除は既存の予定削除確認に未保存メモも破棄されることを含める。

## インメモリ文書・失敗と再試行

DOMの各文書更新は単調増加のrevisionとセッションIDを付け、変換済み・検証済みの文書をnativeのインメモリdraftにも送る。古いrevisionで新しい文書を上書きしない。選択状態だけの変化では全文を送らない。保存時は、このcheckpointがあってもDOMへの最新文書要求を省かない。

- 初回準備中はメモのloadingを表示し、本文入力を受け付けない。タイトルや日時は編集できる。
- 一度も本文が編集可能になっていない準備失敗では、元文書を維持する。メモを変更せず予定を保存できることを説明し、再試行で初期文書を再投入する。
- 編集開始後の変換失敗・保存用本文取得失敗は保存を止める。DOMを破棄せず、同じ本文から取得を再試行する。
- WebView自体が失われた場合は最後に検証できたインメモリ文書を保持する。ただし未受信の文字まで復元できるとは保証しない。「最後に取得できた内容から再読み込み」と失われる可能性を示し、変更がある場合は明示確認後だけ再初期化する。古いDB本文へ黙って戻さない。
- 準備、変換、URLの失敗は固定文言で示し、本文やURLをログ・外部エラー情報へ含めない。失敗時に空文書を代入しない。
- 予定を破棄・保存して閉じるとセッションを破棄する。メモだけの自動DB保存や復元用ファイルは作らない。

## 責務と既存コードへの接続

現行FormattedNoteEditor、Tiptap adapter、EventNoteDocumentV1、native書式ツールバーを再利用する。全画面Modalは予定画面の導線から外す。既存の呼出しがなくなったwrapper・テストの整理は実装計画で決める。

- `src/domain/calendar/event-note.ts`: 文書の検証・正規化・比較・プレーンテキスト投影を維持する。
- `src/features/events/event-note/`: 既存の許可schemaとadapterを維持する。
- `src/features/events/components/formatted-note-editor/`: inline寸法、DOM文書要求・応答、focus・blur・状態・高さ通知を扱う。現在の100vhとonCreate自動focusは埋め込み用へ変更する。
- feature hook（新規のメモdraft調整hookとuseEventEditor）: 要求ID・revision・最新文書・準備失敗・保存ロック・再試行を扱う。DOM/Tiptap型をRepositoryへ渡さない。
- `useEventEditor.save`がメモの取得からpending aggregateまでを一貫して調整する。公開型やhook分割の具体形は実装計画で決めるが、routeは保存結果に応じた通知・戻るの薄い層を維持する。
- 取消・戻るの調整はfeature hookへ置き、Expo Routerの戻る抑止を使う。業務・永続化ロジックを表示コンポーネントへ移さない。
- SQLiteは既存の文書JSONとテキスト投影、予定・通知・例外のtransactionをそのまま利用する。migration・設定追加は不要。
- 実際に他の画面でも使うUIだけ`src/shared/components`へ置く。今回のメモ専用部品はfeature内とする。

Expo DOMは非同期のJSON通信であり、imperative関数の同期戻り値から文書を得ない。セッション・文書要求を跨ぐ応答はIDで検証する。react-native-webviewの既存利用とnavigation制限、`unstable_useExpoModulesBridge: false`を維持する。新しいライブラリや別のHTML保存形式は導入しない。

## アクセシビリティと検証

本文の編集領域・各書式操作・チェック状態へ読み上げ名と状態を付ける。44pt以上の操作領域、明暗テーマのコントラスト、色以外の選択表現、Reduce Motionを維持する。ツールバーは文字拡大時も横スクロール可能とし、DOM本文の文字サイズもOSの拡大率に追随させる。自動フォーカスで予定タイトルから読み上げ位置を奪わない。

先行テストで少なくとも次を固定する。

- 起動時の非focus、既存文書と空文書、対応書式・チェック・URLの維持。
- 最後の1文字、IME確定、最新文書取得後の保存、空への変更、連打・要求順序・古い応答・timeout・離脱・再試行。
- メモだけではRepositoryを呼ばず、予定保存で文書とテキスト投影を一緒に保存すること。
- DB失敗・入力エラー・範囲選択取消で最新メモを保持し、単回／これ以降／全体のnotes overrideが従来と整合すること。
- 未準備の無編集保存と編集後の失敗を区別し、変換失敗・WebView失敗で元文書を空にしないこと。
- ざっくり／きっちり切替・他項目focus・キーボード開閉で文書・選択を失わないこと。
- 破棄確認の継続／破棄、戻る操作、保存中の離脱抑止とロック解除。
- 本文の高さの上下限・スクロール・フォーカス追従は純粋計算と通知境界を自動テストし、OSの動作は実機で別途確認する。

実装後はtypecheck・lint・全Jest・diff check・iOS/Android exportを実行する。小画面、横向き、長文、文字拡大、VoiceOver/TalkBack、ソフトウェア／ハードウェアキーボード、両OSの内外スクロールとIMEは実機確認項目とする。自動テストやexportを実機の成功として扱わない。
